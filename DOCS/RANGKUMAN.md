# Soil Cloud — Rangkuman & Blueprint Bangun Ulang

Dokumen ini berdiri sendiri. Cukup dibaca dokumen ini saja untuk membangun proyek dari folder kosong, tanpa membaca kode lama. Ditulis setelah satu kali percobaan penuh, jadi memuat keputusan, alasan, dan kesalahan yang tidak perlu diulang.

Dokumen terkait di folder ini: `PRD.md` (kebutuhan produk), `design.md` (acuan UI), `KEAMANAN.md` (autentikasi, autorisasi, validasi).

---

## 1. Apa yang dibangun

Sistem monitoring kesuburan tanah untuk PBL (semester 5).

Tiga bagian:

1. **ESP32** di lahan. Membaca sensor tanah, menghasilkan klasifikasi dan rekomendasi lewat model AI di perangkat, lalu mengirim JSON ke cloud.
2. **Soil Cloud API** (Express + Supabase) di Vercel. Menerima data dari ESP32, menyajikan data ke dashboard, menangani login.
3. **Dashboard web** di balik login. Menampilkan kondisi tanah terkini, grafik, rekomendasi, riwayat.

Tujuan: petani tahu kondisi tanah tanpa uji laboratorium tiap kali.

---

## 2. Keputusan yang sudah dikunci

Jangan diutak-atik ulang kecuali ada alasan baru.

| Keputusan | Pilihan | Alasan |
|---|---|---|
| Backend | Express di Vercel, `server.js` | Sudah jalan, mudah dijelaskan |
| Database | Supabase (PostgreSQL) | Gratis, ada dashboard SQL |
| Dashboard langsung ke Supabase (PostgREST)? | **Tidak** | Validasi dan pemetaan kolom hilang, API key tetap harus ditanam di ESP32, satu salah policy = seluruh tabel terbuka |
| Auth | Tabel `users` sendiri + password hash + JWT | Supabase Auth tidak punya kolom username, dan tidak punya PIN |
| Token | JWT stateless, berlaku 7 hari | Tidak perlu tabel `sessions` |
| Penyimpanan token di browser | `localStorage` | Simpel; risiko XSS dicatat sebagai known issue, upgrade nanti ke cookie `httpOnly` |
| Auth ESP32 | Tetap `x-api-key`, tidak berubah | Perangkat tidak bisa "login" |
| Endpoint baca | `GET /api/soil` dengan JWT | `/api/soil/latest` dihapus |
| Device ID | Tidak ada, tidak ditampilkan | Keputusan sadar |
| Signup | Mati. Akun dibuat lewat skrip | Mencegah pendaftaran liar |
| Nama kolom database | **semua huruf kecil** | Percobaan pertama gagal karena campur (`hum`, `temp` kecil; `N`, `pH`, `EC` besar) → bikin pemetaan rapuh |
| Nama tabel | `kesuburan_tanah` dan `users` | `user` kata kunci SQL, bikin repot di SQL editor |

## 4. Skema database

Jalankan di SQL Editor Supabase. Semua nama kolom **huruf kecil**, `id` pakai identity, RLS aktif tanpa policy.

```sql
-- data sensor
create table public.kesuburan_tanah (
  id bigint generated by default as identity primary key,
  timestamp timestamp not null,
  hum numeric,
  temp numeric,
  n numeric,
  p numeric,
  k numeric,
  ph numeric,
  ec numeric,
  ai_label text,
  recommendation text
);

-- akun dashboard
create table public.users (
  id bigint generated by default as identity primary key,
  username text unique not null,
  password_hash text not null,
  created_at timestamptz not null default now()
);

-- kunci akses: hanya server (secret key) yang boleh baca
alter table public.kesuburan_tanah enable row level security;
alter table public.users enable row level security;
```

Skema di atas menormalkan semua nama kolom jadi huruf kecil. Kalau kamu memakai tabel yang **sudah ada** di proyek Supabase saat ini, nama kolomnya masih campur (`hum`, `temp` huruf kecil; `N`, `P`, `K`, `pH`, `EC` huruf besar) dan tabel login masih bernama `user` dengan kolom `password`. Ikuti `PRD.md` bagian 7.5 dan 7.6 untuk keadaan yang ada, atau jalankan pembangunan ulang sesuai SQL di atas.

Dua hal yang wajib benar:

1. `id` harus `generated by default as identity`. Tanpa itu, `POST` gagal dengan `null value in column "id"`.
2. RLS aktif **tanpa policy**. Kalau ada policy yang salah, publishable key bisa membaca data.

## 6. Endpoint

Empat endpoint. Tidak lebih.

| Endpoint | Auth | Konsumen | Balasan |
|---|---|---|---|
| `GET /` | publik | cek hidup | `{ status: "ok" }` |
| `POST /api/login` | publik + rate limit | dashboard | `200 { success, token }` |
| `POST /api/soil` | `x-api-key` | ESP32 | `201 { success, message, data }` |
| `GET /api/soil?limit=40` | `Bearer <JWT>` | dashboard | `200 { success, message, data }` |

Jangan bikin `GET /api/soil/latest`. Endpoint itu hanya ada kalau dashboard belum berlogin, dan pernah bikin satu minggu kerja terbuang karena harus dihapus.

### 6.1 `POST /api/soil`

Header: `Content-Type: application/json`, `x-api-key: <API_KEY>`

Body:

```json
{
  "timestamp": "2026-10-22T08:15:30Z",
  "ph": 6.2,
  "temperature": 29.4,
  "moisture": 48.5,
  "nitrogen": 35,
  "phosphorus": 18,
  "potassium": 24,
  "ec": 0.82,
  "classification": "Sedang",
  "recommendation": "Pemupukan sesuai kebutuhan tanah."
}
```

Validasi wajib, urut:

1. `x-api-key` sama dengan `API_KEY` → kalau tidak, `401 { success: false, message: "Unauthorized" }`.
2. Semua field di atas ada → kalau tidak, `400 ... "Invalid or incomplete data"`.
3. Field numerik (`ph`, `temperature`, `moisture`, `nitrogen`, `phosphorus`, `potassium`, `ec`) bertipe `number` dan finite → kalau tidak, `400 ... "<field> must be a valid number"`.
4. Insert gagal → `500 ... "Failed to save data"`.
5. Sukses → `201`.

Catatan: nilai `0` sah. String angka (`"6.2"`) ditolak. Ini disengaja, ESP32 harus kirim angka.

Validasi semantik (rentang sensor, panjang teks, dan kewajaran `timestamp`) mengikuti `KEAMANAN.md` bagian 5.4.

### 6.2 `POST /api/login`

Body: `{ "username": "petani", "password": "..." }`

| Kondisi | Balasan |
|---|---|
| Field kosong atau bukan teks | `400 { success: false, message: "username dan password wajib diisi" }` |
| Username tidak ada atau password salah | `401 { success: false, message: "Username atau password salah" }` |
| Sukses | `200 { success: true, token: "<JWT>" }` |
| Lebih dari 10 percobaan dalam 15 menit | `429` |

Penting: username tidak ada dan password salah harus memberi **pesan yang sama**, supaya username tidak bisa ditebak.

### 6.3 `GET /api/soil`

Header: `Authorization: Bearer <JWT>`

- Tanpa token, tanda tangan salah, atau kedaluwarsa → `401 { success: false, message: "Unauthorized" }`.
- `limit` opsional, dipotong maksimum 200. Dashboard minta 40.
- Urut `timestamp` menurun.
- `id` tidak diikutkan pada respons.

Balasan:

```json
{
  "success": true,
  "message": "Data retrieved successfully",
  "data": [
    {
      "timestamp": "2026-10-22T08:15:30Z",
      "ph": 6.2,
      "temperature": 29.4,
      "moisture": 48.5,
      "nitrogen": 35,
      "phosphorus": 18,
      "potassium": 24,
      "ec": 0.82,
      "classification": "Sedang",
      "recommendation": "Pemupukan sesuai kebutuhan tanah."
    }
  ]
}
```

### 6.4 Pemetaan nama field

Nama field API **sama** untuk `POST` dan `GET`. Yang berbeda hanya nama kolom database. Satu fungsi pemetaan, dipakai dua arah.

| Field API / ESP32 | Kolom database | Satuan |
|---|---|---|
| `timestamp` | `timestamp` | ISO 8601 |
| `ph` | `ph` | pH |
| `temperature` | `temp` | °C |
| `moisture` | `hum` | % |
| `nitrogen` | `n` | mg/kg |
| `phosphorus` | `p` | mg/kg |
| `potassium` | `k` | mg/kg |
| `ec` | `ec` | mS/cm |
| `classification` | `ai_label` | teks |
| `recommendation` | `recommendation` | teks |
| - | `id` | tidak dikirim |

## 7. Kerangka `server.js`

Urutan bagian. Ini inti yang sulit, sisanya mekanis.

```js
const express = require("express");
const path = require("path");
const bcrypt = require("bcryptjs");
const jwt = require("jsonwebtoken");
const rateLimit = require("express-rate-limit");
const { createClient } = require("@supabase/supabase-js");
require("dotenv").config();

const app = express();
app.use(express.json());

const supabase = createClient(process.env.SUPABASE_URL, process.env.SUPABASE_KEY);
const TABLE = "kesuburan_tanah";

// --- pemetaan nama kolom, satu tempat saja -------------------------------
// device -> database, dipakai saat insert
const toDb = ({ ph, temperature, moisture, nitrogen, phosphorus, potassium, ec, classification, recommendation }) => ({
  ph, temp: temperature, hum: moisture,
  n: nitrogen, p: phosphorus, k: potassium, ec,
  ai_label: classification, recommendation
});

// database -> device, dipakai saat mengirim respons
const toApi = (r) => ({
  timestamp: r.timestamp,
  ph: r.ph, temperature: r.temp, moisture: r.hum,
  nitrogen: r.n, phosphorus: r.p, potassium: r.k, ec: r.ec,
  classification: r.ai_label, recommendation: r.recommendation
});

// --- auth perangkat ------------------------------------------------------
const authenticateApiKey = (req, res, next) => {
  if (req.headers["x-api-key"] !== process.env.API_KEY) {
    return res.status(401).json({ success: false, message: "Unauthorized" });
  }
  next();
};

// --- auth pengguna -------------------------------------------------------
const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  limit: 10,
  message: { success: false, message: "Terlalu banyak percobaan, coba lagi nanti" }
});

const authenticateUser = (req, res, next) => {
  const header = req.headers.authorization || "";
  const token = header.startsWith("Bearer ") ? header.slice(7) : null;

  if (!token) return res.status(401).json({ success: false, message: "Unauthorized" });

  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch (error) {
    res.status(401).json({ success: false, message: "Unauthorized" });
  }
};

// --- endpoint -----------------------------------------------------------
app.get("/", (req, res) => res.json({ status: "ok", message: "Soil Cloud API is running" }));

app.post("/api/login", loginLimiter, async (req, res) => {
  const { username, password } = req.body || {};

  if (typeof username !== "string" || typeof password !== "string" || !username || !password) {
    return res.status(400).json({ success: false, message: "username dan password wajib diisi" });
  }

  const { data, error } = await supabase
    .from("users")
    .select("id, username, password_hash")
    .eq("username", username)
    .maybeSingle();

  if (error) return res.status(500).json({ success: false, message: "Gagal memproses login" });

  const cocok = data && (await bcrypt.compare(password, data.password_hash));

  if (!cocok) {
    return res.status(401).json({ success: false, message: "Username atau password salah" });
  }

  const token = jwt.sign({ sub: data.id, username: data.username }, process.env.JWT_SECRET, {
    expiresIn: "7d"
  });

  res.json({ success: true, token });
});

app.post("/api/soil", authenticateApiKey, async (req, res) => {
  // validasi (bagian 6.1), lalu:
  const { data, error } = await supabase
    .from(TABLE)
    .insert([{ timestamp: req.body.timestamp, ...toDb(req.body) }])
    .select();

  if (error) return res.status(500).json({ success: false, message: "Failed to save data", error: error.message });

  res.status(201).json({ success: true, message: "Data saved successfully", data: data.map(toApi) });
});

app.get("/api/soil", authenticateUser, async (req, res) => {
  const limit = Math.min(Number(req.query.limit) || 200, 200);

  const { data, error } = await supabase
    .from(TABLE)
    .select("*")
    .order("timestamp", { ascending: false })
    .limit(limit);

  if (error) return res.status(500).json({ success: false, message: "Failed to retrieve data", error: error.message });

  res.json({ success: true, message: "Data retrieved successfully", data: data.map(toApi) });
});

// --- untuk Vercel -------------------------------------------------------
const https = require("https");
const fs = require("fs");
if (process.env.NODE_ENV !== "production") {
  // HTTPS lokal dengan sertifikat di certs/, opsional saat development
  try {
    const options = {
      key: fs.readFileSync(path.join(__dirname, "certs", "key.pem")),
      cert: fs.readFileSync(path.join(__dirname, "certs", "cert.pem"))
    };
    https.createServer(options, app).listen(process.env.PORT || 3000);
  } catch (error) {
    app.listen(process.env.PORT || 3000);
  }
}

module.exports = app;
```

Alasan `select("*")` lalu `toApi()`, bukan alias PostgREST (`ph:ph`): nama kolom pernah tidak konsisten huruf besar/kecil dan PostgREST mencocokkan nama secara sensitif. Mengambil semua kolom lalu memetakan di JavaScript menghapus seluruh kelas kesalahan itu, dan bila skema berubah, cukup ubah `toDb`/`toApi`.

## 8. `scripts/create-user.js`

Satu-satunya cara membuat akun. Tidak ada endpoint signup.

```js
require("dotenv").config();
const bcrypt = require("bcryptjs");
const { createClient } = require("@supabase/supabase-js");

const [username, password] = process.argv.slice(2);

if (!username || !password) {
  console.error("Pakai: node scripts/create-user.js <username> <password>");
  process.exit(1);
}

const supabase = createClient(process.env.SUPABASE_URL, process.env.SUPABASE_KEY);

(async () => {
  const password_hash = await bcrypt.hash(password, 10);
  const { error } = await supabase
    .from("users")
    .upsert({ username, password_hash }, { onConflict: "username" });

  if (error) {
    console.error("Gagal:", error.message);
    process.exit(1);
  }

  console.log(`Akun "${username}" siap.`);
})();
```

Jalankan: `node scripts/create-user.js petani rahasia123`

## 9. Dashboard (frontend)

Vanilla HTML/CSS/JS. Chart.js dan font dari CDN. Tanpa framework.

### 9.1 `index.html`

- `lang="id"`, font Plus Jakarta Sans, `style.css`.
- Tautan `Lewati ke konten utama` (`skip-link`).
- **Layar login** (tampil sebelum autentikasi): judul, kolom username, kolom password, tombol masuk, area pesan error. Satu kolom, label terlihat, bisa dioperasikan keyboard.
- Header: nama aplikasi, indikator status, waktu update terakhir, tombol Perbarui, tombol Keluar.
- Navigasi bagian: Ringkasan, Monitoring, Rekomendasi, Riwayat.
- Banner error tersembunyi dengan tombol Coba Lagi.
- 8 kartu: N, P, K, pH, Suhu, Kelembapan, EC, Tingkat Kesuburan.
- Grafik N/P/K dengan `role="img"` + `aria-label`.
- Panel tingkat kesuburan + teks rekomendasi.
- Tabel riwayat: Waktu, pH, Suhu, Kelembapan, N, P, K, EC, Kesuburan. Ada `caption` sr-only dan `scope` pada header.
- Footer: sumber data + info pembaruan otomatis 30 detik.

### 9.2 `app.js`

Inti perilaku:

1. Saat load, cek apakah ada token tersimpan.
   - Tidak ada → tampilkan layar login, **jangan** fetch.
   - Ada → sembunyikan login, mulai `loadData()` dan interval.
2. `loadData()` → `fetch("/api/soil?limit=40", { headers: { Authorization: "Bearer " + token } })`.
   - `401` → hapus token, tampilkan login dengan pesan sesi berakhir.
   - Sukses → render kartu, grafik, tabel.
3. Login → `POST /api/login`. Sukses → simpan `token`, mulai dashboard. Gagal → tampilkan pesan error dari server.
4. Keluar → hapus token, tampilkan login.
5. Polling 30 detik. Muat ulang saat tab kembali aktif (`visibilitychange`). Abaikan fetch ganda (`isFetching`).
6. Status Online kalau `timestamp` data terbaru ≤ 2 menit, kalau lebih → Offline. Belum ada data → Menunggu data.
7. Klasifikasi dibaca dari teks `classification`: mengandung `tinggi`/`high` → Tinggi, `rendah`/`low` → Rendah, `sedang`/`medium` → Sedang, lainnya → idle.

Format angka kartu: N/P/K 0 desimal, pH/suhu/kelembapan 1 desimal, EC 2 desimal.

## 10. Kontrak ESP32

- Kirim `POST /api/soil` dengan header `x-api-key` dan `Content-Type: application/json`.
- Body sesuai bagian 6.1. Angka harus angka, bukan string.
- Kirim `timestamp` tiap pengukuran.
- Interval kirim ≤ 2 menit, supaya status di dashboard tetap Online. Kalau lebih lama, dashboard akan bilang Offline.
- Firmware tidak perlu tahu apa pun soal login dashboard.

## 13. Kesalahan yang pernah terjadi, jangan diulang

| Kejadian | Sebab | Cara menghindar |
|---|---|---|
| `POST /api/soil` selalu gagal | Nama tabel dan kolom di kode tidak cocok dengan Supabase (`soil_measurements` vs `kesuburan_tanah`, `Hum` vs `hum`) | Jalankan SQL bagian 4 apa adanya, lalu pakai `toDb`/`toApi` |
| Dashboard mati saat endpoint lama dihapus | `/api/soil/latest` dihapus sebelum frontend dipindah | Pindahkan frontend dulu |
| Pemetaan kolom rapuh | Nama kolom campur huruf besar/kecil | Semua kolom huruf kecil |
| `POST` dan `GET` memberi nama field berbeda | `POST` memakai `insert().select()` mentah, `GET` memakai alias | Dua-duanya lewat `toApi` |
| Secret key Supabase bocor | Terlihat di screenshot yang dibagikan | Rotasi key, jangan pernah screenshot `.env` atau dashboard key |
| Token selalu `401` | `JWT_SECRET` berbeda antara lokal dan Vercel | Samakan nilainya |
| Login selalu gagal walau password benar | Hash dibuat `bcryptjs`, dicocokkan dengan `bcrypt` (paket berbeda) | Pakai satu paket saja |
| Insert gagal `null value in column "id"` | Kolom `id` tidak punya nilai otomatis | Pakai `generated by default as identity` |
| File dashboard tidak termuat | Mengandalkan `express.static()` di Vercel | Taruh di `public/**` |
| Riwayat git tercemar | `node_modules/` dan `certs/` pernah ter-commit | Pastikan `.gitignore` benar sejak commit pertama |
| `npm start` gagal | `main` di `package.json` menunjuk `index.js` | Set `main` ke `server.js` |
